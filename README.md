# N-Link

> 为尼康 Z 系列微单打造的 Android 连接与遥控伴侣 —— 稳定连接 · 极速传图 · 全功能遥控。

N-Link 是一款面向尼康 Z 系列微单（Z50II / Z6III / Z8 / Z9 / Zf 等）的开源 Android 应用，打通 **连接 → 浏览 → 传输 → 遥控 → 监看** 的完整链路，以「永不断联」为核心卖点：

- **稳**：BLE 心跳保活 + 前台服务常驻，断线自动重连（< 3s）
- **快**：USB / WiFi 双高速通道，智能调度与自动回退
- **全**：照片传输 + 远程快门 + 实时取景 + 参数管理四合一
- **简**：一次配对、自动恢复、零上手成本

## ✨ 功能特性

### 三通道连接

| 通道 | 能力 |
|------|------|
| **BLE** | **辅助通道**：配对引导（免输入下发 WiFi 凭证）· 心跳保活 · GPS 注入 · 遥控快门 · 状态读取。采用尼康 BLE 配对协议与 Blowfish 加密 |
| **WiFi** | **主数据通道**：相机发现（mDNS `_ptp._tcp` / `_nikon._tcp` + 子网扫描），PTP/IP（ISO 15740）全量会话，承载实时取景与全分辨率传输 |
| **USB** | 有线优先通道，相机插入自动唤起，keepalive 保活，支持 USB Live View 与遥控；v1.2.0 完成全链路优化（PTP 事务层容器重组重建、USB 实时监看打通、相册加载与断连修复） |

> **通道定位**：BLE 负责「握手引导 + 状态注入 + 低功耗保活」，WiFi PTP/IP 与 USB 负责「搬运数据」。
> BLE 受 GATT 带宽限制，**不承载实时取景与大文件传输**（结论：可行，作为辅助通道保留并继续投入）。

### 照片浏览与传输

- 相机存储卡照片列表，18 张/页分页加载 + 缩略图实时预览，默认按拍摄时间降序（新拍的在前）
- 格式筛选（全部 / 照片 / 视频 / RAW / JPG），筛选无结果时自动兜底提示
- 单张 / 批量 / 筛选 / 全部下载，支持**跳过已下载**与剩余数量进度提示，传输队列支持暂停、恢复、取消
- **断点续传**：中断自动从断点恢复，失败自动重试并回退备用通道，传输去重；相册列表滑动节流，长列表不卡顿
- 归档至 `DCIM/N-Link`（MediaStore / Scoped Storage），「本地照片」Tab 随时回看，下载完成后触发媒体库扫描

### 远程遥控拍摄

- 两段式快门：半按对焦 → AF 收敛后自动释放快门，确保合焦
- **B 门**遥控（实时曝光计时）、**定时拍摄**（2s/5s/10s/自定义）、**间隔拍摄**（延时摄影）
- 曝光三要素（光圈 / 快门 / ISO）、白平衡、对焦模式、测光等参数实时读写
- 画面模式置于顶部下拉芯片快速切换，拍摄模式下拉分体按钮切换；更多动作长按弹出教程气泡

### 实时取景（Live View）

- 实时画面传输，端到端低延迟（目标 < 200ms @ WiFi 5GHz）
- 触摸对焦、手动对焦驱动、双指缩放
- 构图网格叠加（三分线等）、全屏沉浸体验、重力感应横竖屏

### 连接稳定性

- 前台连接服务（`connectedDevice|dataSync`）保活 + 开机自启 + WorkManager 健康检查
- 连接状态机：通道升级、失败回退、指数退避重连；WiFi STA 扫描失败原因可见化（权限 / 定位开关 / 系统限制逐项提示）
- 实时连接状态仪表盘与厂商后台策略适配

### 其他

- **快门次数查询**：机身 PTP 不支持时自动经 EXIF 解析（Digeeker 协议）
- 拍摄参数预设管理、传输完成通知、RAW 处理策略
- **应用内更新**：读取 GitHub Releases 元数据（仅提示正式版），解析夸克网盘回退链接写入本地缓存，更新弹窗纯文本呈现
- 支持与反馈页（问题反馈 / 交流群 / 捐赠入口）
- 黑白极简设计语言：DayNight 自适应主题、8px 圆角、PressEffect 按压反馈

### WiFi STA 连接教程

> 适用场景：**相机作为客户端加入网络**（连手机热点，或与手机连同一路由器）。
> 尼康相机在 STA 模式下有「信任主机」门控：**首次使用必须先注册一次**，否则 PTP/IP 握手会被相机拒绝（日志表现为 `fail_reason=1`，即「连接被占用」）。

#### 第 1 步 · 首次使用先注册主机（只需做一次）

1. 相机开启 WiFi 热点（AP 模式），手机在系统设置里连上该热点；
2. App 切到「WiFi-AP」页签 → 连上相机；
3. 切到「WiFi-STA」页签 → 点「**STA 主机注册**」→ 按相机屏幕提示确认（约 10 秒）；
4. 出现「主机注册完成」即成功。相机已记住本机，之后长期有效，无需重复注册。

> 「STA 主机注册」按钮常驻在 WiFi-STA 页签内。**相机尚未记住本机时按钮显示为强调色**，注册完成后转为描边样式。

#### 第 2 步 · 每次 STA 连接

1. 相机菜单进入「**WiFi 连接（STA mode）**」，选择连接手机热点（或同一路由器），**停在连接的等待画面**；
2. 手机开启个人热点（或与相机处于同一 WiFi）；
3. App 切到「WiFi-STA」页签，选择子模式（同一 WiFi / 连接手机热点）→ 点「**扫描相机**」→ 点「**连接相机**」。

#### 失败提示对照

| 现象 | 原因 | 处理 |
|------|------|------|
| 握手被拒（`fail_reason=1`「连接被占用」） | 相机未停在「WiFi 连接（STA mode）」等待画面，或本机尚未注册为主机 | 先在相机上进入「WiFi 连接（STA mode）」并停在等待画面；若仍失败，执行第 1 步注册 |
| 扫描不到相机 | 权限 / 路由未就绪 / 相机不在同一子网 | 按 App 内诊断文案处理（定位权限、子网、ARP 条目数） |
| 注册提示「相机未接受预备注册」 | 相机屏幕不在可接受连接的画面 | 让相机处于连接等待画面后重试注册 |

### v3.4.1 — 2026-10-22

本版收口 STA 相册的保护筛选与传输稳定性，并把相册快速滑动的渲染链路重做一遍。

- **连接**：STA「连接到电脑」下按需补读机内保护位，首次点「已保护」时读取，读不到明确提示并退回「全部」；「已筛选」仍同时覆盖保护与评级，两个入口语义互不吞并
- **传输**：整段下载期间放宽命令通道超时并豁免心跳 / 事件静默判死，视频与大文件不再在分块间隙被误判断链；断线后续传先等待重连，最长 30 秒
- **传输**：保存按视频 / 图片 / 下载目录分流写入 MediaStore，修复视频或 `Download/N-Link` 下照片保存失败；失败时给出剩余空间、权限或写入中断等可核对原因
- **预览**：删除最后一张或连续删除时夹紧下标并精确移除页面，修复 ViewPager2 越界闪退与停在已不存在尾页的问题
- **相册**：重做滚动链路——滚动态停止背景采集与透镜重算、缩略图按单格 payload 刷新、后台状态延迟到停稳后提交，快速上下滑不再被整树绘制和整段重绑挤占帧预算
- **相册**：滚动停止后统一补发可见项缩略图并就地恢复占位，停稳即出图；格子布局压平、固定尺寸、扩大回收池并关闭 change 动画，降低新行绑定成本
- **设备页 / 设置页**：滚动回调接入冻结采集，快速滑动时的周期性卡顿同步收敛
- **测试**：新增滚动采集契约与格子布局回归用例，覆盖「滚动中零采集 / 停稳补采」和正方形格子的几何约定

### v3.4.0 — 2026-10-20

STA 链路补上相册直读；AP 侧收口存储卡读数与实时取景的数据面。

- **连接**：相机以「连接到电脑」方式接入路由器或手机热点（STA）时，机身对常规对象命令加了访问锁，相册此前完全读不出；本版改用机身私有命令直读，列表、缩略图、预览与原图下载恢复可用
- **连接**：直读也不可用的机型不再逐条重试空转，直接提示改用热点直连或 USB
- **相册**：机身不提供文件名时按卡内编号生成（前缀可能与机身设定不同）
- **设备页**：AP 模式下「存储卡」格显示容量、剩余空间与占用比例，此前恒为占位符
- **监看**：AP 取景期间保持 Wi-Fi 高性能、取帧改为连续拉取，相机忙碌（0x2019 / 0xA004）时退避而不是按固定节奏猛敲
- **监看**：取帧搬运去掉扩容与二次裁剪；AP 开播不再并发执行诊断性属性探测，首帧窗口不被抢通道
- **拍摄页**：取景框高度跟随画面比例，去掉画面下方那条多余黑带
- **提示**：机身拒绝操作时的文案由「相机端未确认连接」改为「相机端未放行该操作」

### v2.3.1 — 2026-09-21

快门次数从「查不到」做到可交付：修掉两处会让所有真机一律失败的结构错误，并把云端兜底收进授权门。

- **根因**：MakerNote `0x927C` 实际位于 Exif 子 IFD（`0x8769` 指向），旧实现只在 IFD0 找；且 IFD 位置从未试现代 D/Z 的 `+18` —— 两处叠加使本机解析**从未成功过**，云端解析从「兜底」被顶成了主路径
- **自校验**：按形态枚举候选 (IFD 位置 × 字节序)，再用固件恒等式 `0x00A5 + 0x00A6 == 0x00A7` 反选真正对齐的那一个；只过数值合理性、未过恒等式的读数标「未校验」，不假装成功
- **字节序**：MakerNote 的字节序可以与主 TIFF 头相反（真机 D2Hs / D70 即大端笔记 + 小端机身），因此不做「尼康一律小端」的假设
- **样张挑选**：由「文件最小」改为「拍摄时间最新 + NEF 优先」——旧选法会挑到卡上留存的旧照片，而 `0x00A7` 记的是拍摄那一刻的计数，于是报出一个偏低的假数字
