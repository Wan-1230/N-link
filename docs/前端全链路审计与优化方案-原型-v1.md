> 方法：**静态代码审计 + Chromium 真实渲染实测**（Playwright 1.62，5 档视口 × 深浅双主题 × 四页面截图 + 计算样式/几何/对比度断言），全部结论可复现，复现命令见 §7

## 〇、总评

原型作为「设计体系可运行文档」底子是好的：token 化完整（色板/字号 6 档/间距栅格/圆角/动效三档 + 曲线）、零外部请求（无图片无字体请求，CSS 渐变 + 内联 SVG 全矢量）、深浅双主题、四页关键界面全覆盖。**问题不在底子，在执行层**——与 v1.2 规划文档对 app 侧的判定同构。

本轮新发现 **1 个静态阅读不可见、只有真实渲染才暴露的 P0 视觉缺陷**：空 Snackbar 药丸常驻悬浮（浅色主题为黑色药丸、深色为白色药丸，四页全部可见）。另确认 2 个 P0（长文案裁切、三级文字对比度双主题不达标）与 1 个 P1（切页 57px 布局跳动）。

| 维度 | 评级 | 一句话结论 |
|---|---|---|
| 代码结构 | B- | 单文件可接受（原型定位），但 45 处内联 onclick、4 个 `<main>`、全树 MutationObserver 是硬伤 |
| 资源加载 | A | 0 子资源请求、全矢量、load 18.7ms——已到单文件原型最优，无需「合并压缩」式优化 |
| 渲染性能 | B+ | 动画全部 compositor-friendly；扣分在 3 处 20px backdrop-blur 常驻 + 全树 class 监听 |
| 交互体验 | C+ | 缺 hover/focus 态、44dp 触达大面积不达标、主题不持久化、reduced-motion 覆盖不全 |
| 视觉正确性 | **C** | 空 Snackbar 常驻 + 长文案裁切 + 切页跳动，三个都是肉眼可见级 |
| 无障碍 | D | 键盘零可达、`user-scalable=no`、16/16 按钮无 aria-label、对比度不达标 |
| 构建配置 | 无 | 无 package.json/构建/lint——原型可裸奔，但缺「改完自动验」的闸门 |

## 二、分维度详述

### 2.1 资源加载与构建配置（当前 A，缺的是「闸门」不是「优化」）

实测：0 子资源请求、transfer 47,319 B、DCL 16ms / load 18.7ms、控制台 0 错误。单文件原型「合并/压缩/拆分」收益极低——**真正缺的是改完自动验的机制**：

- 无 package.json / 构建 / lint。对照 app 侧已有 `tools/check_ui_tokens.py`（四条红线），原型侧应有同款 CSS 闸门：裸值字号、字符图标、`:root` 外硬编码色、对比度自动计算。
- 无 favicon（浏览器默认请求 `/favicon.ico` 404）。
- 部署层（若上 Cloudflare Pages）应配：文件名 content-hash + `Cache-Control: immutable, max-age=31536000` + Brotli。

### 2.2 渲染性能（B+）

- **3 处 20px `backdrop-filter` 常驻**（topbar/multibar/dock）：sticky topbar 在滚动时每帧重算 backdrop，中低端 Android 上是可感知成本。建议 blur 20→14px 并保留 `saturate(1.4)`（观感损失极小），或对 `prefers-reduced-motion`/低端场景降级为纯半透明。
- **动画清单健康**：pageIn/shimmer/dotPulse/pill 全走 transform+opacity（compositor-friendly），按压反馈 scale(.92-.97) 统一。唯一 layout 属性动画是 `.pbar i{transition:width .6s}`——且 .6s 是 token 外裸值（slow 档 380ms 内应收口）。
- **全树 MutationObserver**（D13）：每次任意 class 变化触发回调，纯浪费；应改为 `go('p2')` 内直接触发一次。
- 18 个相册 tile 一次 innerHTML 插入，无虚拟滚动必要（真实数据接入时再上 IntersectionObserver 懒加载 + 分页，见 §3.5）。

### 2.3 交互体验与无障碍（C+/D）

见 D5-D9、D15。汇总成三条主线：**反馈完整性**（hover/focus-visible 缺失、reduced-motion 半残）、**触达与可及**（44dp、键盘、aria-label）、**状态诚实**（主题文案声称跟随系统实则没有）。

### 2.4 代码结构与可维护性（B-）

- 45 处内联 `onclick`：原型演示可接受，但阻碍 CSP 与事件 delegation；建议收敛为 `data-go`/`data-act` + 顶层委托（一举解决 D6 键盘可达——委托时统一补 `role`/`tabindex`/键盘回车）。
- 4 个 `<main>`：改 1 main + 4 section，成本 5 分钟。
- CSS 420 行单块：可拆 `tokens.css / components.css / pages.css` 三文件（若原型演进为设计系统文档站则值得；否则维持单文件 + minify 脚本即可，见 §3.6 P2）。

### 2.5 视觉噪音清理清单（「简洁、紧凑、大方，高级感」直接相关）

| 噪音源 | 位置 | 处置 |
|---|---|---|
| 字符图标 ✓ ◐ ℹ › ×5 | 顶栏/设置页 | 全部换成与 dock 同款 24 viewBox 线性 SVG（currentColor），同步补 aria-label |
| demo-note ×3 | p0/p2/p3 | 正式版移除；保留则收敛为 1 条页脚 |
| hero 四态循环演示钩子 | L505/786-800 | 保留函数但默认只暴露 connected/failed 两态（演示入口改长按或删除） |
| `.qi{font-size:0}` 遗留 | L253 | 删除 |
| `title` 属性当 tooltip | 多处 | 移动端无效；桌面保留无妨，正式版建议自绘或删 |
| `.act.ghost` 与 `.mb.ghost` 重复定义 | L303/L322 | 合并为 `.btn-ghost` |

## 三、优化方案（按维度）

### 3.1 代码重构
1. 事件委托：45 处内联 onclick → `data-go`/`data-act` 属性 + document 级委托；委托时给可点元素统一补 `role="button" tabindex="0"` + Enter/Space 处理（同时解 D6）。
2. 语义化：4 main → 1 main + section；svg 补 `aria-hidden`（已有大部分）。
3. `toast()` 改 textContent + 可选受控高亮参数（`toast(msg, {highlight:'OK'})` 内部拼装，不直接吃 HTML）。
4. MutationObserver 删除，进度条重放改 `go()` 钩子。

### 3.2 资源（保持零请求优势，补 favicon 与部署缓存）
- favicon 改内联 `data:image/svg+xml` （尼康黄 M 标，0 请求）。
- 部署：content-hash 文件名 + immutable 缓存头 + Brotli（Cloudflare Pages 默认 Brotir，只需 hash 策略）。

### 3.3 缓存策略
- 主题选择：`localStorage['nl-theme']`，初始值读 `prefers-color-scheme`（对齐设置页「跟随系统」文案，解 D8）。
- 原型无数据请求，无 HTTP 缓存对象；上述即全部。

### 3.4 请求合并
无请求可合并（已 0 请求）。若拆文件（§3.6），保持 CSS ≤2 + JS ≤1，不新增域名/字体外链。

### 3.5 按需加载
- 现状四页 DOM 常驻（18 tile + 骨架）成本可忽略，**不需要**代码分割。
- 预留接口：相册接入真实数据时，`fillGrid` 改生成 `<img loading="lazy">` + IntersectionObserver 分批；超过 200 项上虚拟滚动。本次不动。

### 3.6 渲染效率
- backdrop blur 20→14px（三处）；`.pbar` width 动画改 `transform:scaleX()`（需 transform-origin:left）；.6s 收口进 motion token。
- 删除全树 MutationObserver。
- 不加 `will-change`（常驻 will-change 是反模式；按压反馈用 :active 已够）。

### 3.7 用户体验（含视觉噪音清理）
- Snackbar 三件套门控 + 自适应位置 + 长文案策略（见 P0-1/2/3）。
- 主题持久化 + 系统跟随。
- 补 `:hover`（桌面）与 `:focus-visible`（键盘，2px 黄环 + offset）。
- reduced-motion 全覆盖：shimmer/pageIn/多选栏/pill 全部纳入一条 `@media`。
- 触达 44dp：hero-badge/errbar button/act/switch/chip/iconbtn/segment/mb 八处（视觉尺寸可不变，用 padding/透明热区扩到 44dp，保持「紧凑」观感）。
- 字符图标矢量化 + demo-note 清理（§2.5 清单）。
- 深色主题补 `color-scheme: dark light` meta（修桌面滚动条浅色问题）。
- `user-scalable=no` 删除（a11y 合规，双指缩放交给用户）。

## 八、刻意不做的事

- **不拆文件/不上框架**：原型定位是「零依赖单文件、手机浏览器直接打开」，拆分为 P2 可选项且默认不做。
- **不引 Web 字体/图标库/CDN**：零外部请求是当前最大资产，任何外链都是净损失。
- **不虚拟滚动/不代码分割**：18 个演示 tile 没有性能问题，真实数据接入时再议（§3.5 已留接口）。
- **不动黑白灰+黄与玻璃三处纪律**：本方案所有结论都在强化既有决策（包括把跑偏的执行拉回规范）。
- **不改 app 侧已真机验收布局**：token 漂移项（P0-5）只改原型 CSS 变量值并同步文档口径，不反向要求 app 返工。

P0 五项全部是「小改动、大收益、低风险」型（合计约 6 行门控 CSS + 2 个属性 + 1 处换行策略 + 1 处导航策略 + 2 个 token 值），建议本批落地；P1 十三项次日批；P2 并入原型工具链批次。**每项独立 commit + 截图回归**，与 v1.2 规划的回退手段一致。
