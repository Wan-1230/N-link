**改动范围严格收敛在玻璃包内**：6 个 Kotlin 文件 + 2 个 token 文件，未动布局、未动连接层、

## 0. 先说清楚两件事

### 0.1 目标对象

接到需求时核对：磁盘上唯一的 Web 前端是 `ai-learning-site`（仅 1 处 `backdrop-filter`），
与"全链路液态玻璃"不符。经确认，目标是 **N-Link Android 工程**的原生 UI 层。

### 0.2 规范落地的天然边界（能力限制，不是 bug）

Apple 的 Liquid Glass 是**系统合成器**里的材质：折射走真实 SDF + 位移贴图，高光跟随设备
姿态，多面玻璃在同一容器里互相折射。Android 侧没有对应物，本仓的做法是
"1/8 降采样纹理 + CPU box blur + 自绘 Drawable"。下表是**无法靠改代码抹平**的部分：

| Apple 能力 | Android 现状 | 本仓替代 / 降级 |
|---|---|---|
| `GlassEffectContainer`（多面玻璃互相折射、合并采样） | 无 | 一个内容源一张共享纹理（多面复用同一次采集） |
| AGSL `RuntimeShader` 真·lensing | 要 API 33 | CPU 在小纹理上做等价数学（`GlassLens.warp`），API 29 起可用且更省 |
| 折射随设备姿态 / 陀螺仪变化 | 无传感器接入 | 静态折射，仅随内容滚动更新 |
| 材质厚度 / 色散的原生参数 | 无 | 手工 token（`lensStrengthDp` / `magnify` / `dispersion`） |
| 窗口级实时背景模糊 | 要 API 31 | `FLAG_BLUR_BEHIND` + 自动回退不透明面板 |

结论：**在同屏玻璃面数受控（≤4）、内容静态或缓速滚动的场景下可以达到接近的观感**；
高速 fling + 多面叠加时，Android 只能做到"糊度与折射正确"，做不到"光学正确"。

## 1. 缺陷清单（P0：真实 bug，会导致可见错误）

| # | 缺陷 | 成因 | 影响范围 | 位置 |
|---|---|---|---|---|
| 1 | **BottomSheet 双重入场动画** | `hookSheetPanel` 调的是单参重载 `applyBlurBehind(window, context)`，`animatePanel` 默认 **true**；但注释明确要求 sheet 为 false（sheet 自带 slide-up）。实现与注释相反 | 所有 `NlGlass.sheet()`：相册详情、监看设置面板。表现为"面板先缩着淡入、再滑上来"的错位 | `NlGlass.kt` |
| 2 | **描边被强制加粗一倍** | `stroke.strokeWidth = m.strokeWidthPx.coerceAtLeast(onePx)`，`onePx = density`。3x 屏上把 0.5dp 设计值顶成 3px = **1dp** | 全部玻璃面。这正是"塑料边框"观感的来源；`glass_stroke_w_thin` 这个 token 从来没生效过 | `GlassSurfaceDrawable.draw` |
| 3 | **模糊半径静默截断** | `radius = dp(blurDp) * downscale` 后 `.coerceIn(1, 12)`。12 纹理 px 在 3x 屏只折合 `12×8/3 = 32dp` | `glass_blur_xl`(60dp) 的 HUD **从未拿到过它要的糊度**；且截断值随密度漂移（2x→48dp、3x→32dp），同一份 token 在不同手机上是两种材质 | `GlassBackdrop.refreshNow` |
| 4 | **模糊未预乘 → 边缘灰黑晕** | `Bitmap.getPixels()` 给的是**非预乘** ARGB，alpha=0 的像素 RGB 仍是 0。滑窗算术平均把黑色算进邻域 | 被自我屏蔽的玻璃区域、内容未铺满的空白全是这种像素 → 每条玻璃边缘外翻一圈灰黑晕。"毛玻璃发灰、脏"的主因 | `BoxBlur.blur` |
| 5 | **HUD 关玻璃后比 v2.2 更黑** | 关玻璃时画 `opaqueTint`（把半透明 tint 的 alpha 钉成 255）。`glass_tint_scrim` 是 `#99000000`(60% 黑)，钉完是**纯黑**，而 v2.2 的 `liveview_scrim` 正是 60% 黑 | 监看 / 预览参数条、顶栏底片。**违反回退闸门要求的逐像素相等（AC-12）** | `GlassTokens` / `GlassSurfaceDrawable` |
| 6 | **纹理回收通道没接线** | `GlassCoordinator.release()` 全仓 **零调用点**。PRD §8.3 写了"内存吃紧时释放"，但从未实现 | 后台 / 低内存时纹理不归还，只在进程死时才释放 | `GlassBackdrop` |
| 7 | **Drawable 像素缓存只增不减** | `lensOut` 位图随 `applyGlass` 新建；开关切换 / 切页 / 旋转都会重复调用，旧 drawable 虽可被 GC，但抱着的那张位图要等 GC | 长时间反复切页后内存持续爬升 | `GlassSurfaceDrawable` |
| 8 | **色散丢 alpha** | 色散分支用 `Color.rgb()`，alpha 被钉成 255 | 当前 `dispersion` 默认关所以不触发；**一旦开启**，纹理里的透明区域会变成不透明色块 | `GlassLens.warp` |

## 2. 与苹果原生观感的差距清单（P1/P2：质量与可访问性）

| 维度 | 现状 | 苹果原生 | 差距性质 |
|---|---|---|---|
| **模糊采样质量** | 3 趟 box blur（≈高斯），但非预乘、半径被截断 | 合成器级、各向同性、半径无截断 | **已修**（缺陷 3、4） |
| **镜面高光** | 顶部一条铺满**面高一半**的白色渐变；62dp 的 dock 白掉 31dp，读作磨砂亚克力 | **贴着上沿的极亮细线** + 快速衰减 | **已修**：收窄到 `min(35%, 16dp)`，并新增上沿亮线 |
| **内阴影 / 厚度** | 完全没有。只有外描边 + 底边 1px 线 | 底边内侧短暗渐变，撑出"厚度" | **已修**：新增底边内阴影带 |
| **材质分层** | tint + 模糊两层 | 模糊 → tint → 高光 → 内阴影 → 描边，五层各有独立 alpha | 已补齐到五层 |
| **对比度自适应** | 用**整屏平均**亮度判定 | 按**材质所在区域**自适应 | **已修**：改为本面区域亮度 + EMA 平滑 |
| **深浅色适配** | token 成对完整；但夜间阴影压到 4% 近乎不可见，层级全交给 rim | 夜间仍有可辨层次 | 已补镜面亮线（夜间 45%）+ 内阴影（夜间 20%） |
| **滚动性能** | 150ms / 70ms 节流，1/8 纹理，滑窗 O(1)/px | 合成器零 CPU 成本 | **架构性差距**，见 §0.2 |
| **reduced-motion** | 只看 App 内开关，**不看系统「移除动画」** | 系统级 Reduce Motion 全局生效 | **已修**：对接 `animator_duration_scale` |
| **高对比度文字** | 已对接 `accessibility_high_text_contrast_enabled` ✓ | — | 无差距 |
| **同屏玻璃配额** | `reportBlurNeed` 只增不减 → HUD 退场后 dock 仍按 60dp 糊 | 按需 | **已修**：每次采集前重算 |

## 7. v2.6.3 增补 —— 对照开源实现重做折射

用户点名两个参考：**QmDeve/AndroidLiquidGlassView**（主）、**QWEA0/Liquid-Glass-Android**（辅）。

### 7.1 先说结论：都不能直接引入

| 项目 | 协议 | 体系 | 硬伤 |
|---|---|---|---|
| QmDeve `com.qmdeve.liquidglass:core:1.1.0` | MIT | View | **要 API 33**，低于 Android 13 直接不渲染任何效果。本仓 minSdk 29，接进来 Android 10/11/12 全裸奔 |
| QWEA0 `com.github.QWEA0:liquidglass:v2.0.11` | MIT | View | minSdk 24 没问题，但**带 NDK**（arm64-v8a / armeabi-v7a 预编译 .so），包体 + 构建链都是新负担 |

所以走的是**把它们的数学搬进现有 CPU 管线**，不是换库。现有架构（1/8 降采样纹理 +
自绘 Drawable）在 API 29~36 是同一条路径，这个收益不值得为换库放弃。

### 7.2 从 QmDeve 的 AGSL shader 搬了三件事

它的 shader 在 `core/src/main/res/raw/liquidglass_effect.agsl`，核心就三行：
`d = circleMap(1 - -sd/refractionHeight) * refractionAmount`、
`circleMap(x) = 1 - sqrt(1 - x²)`、`refractedCoord = coord + d * normalize(gradSdRoundedRect(...))`。

| 改动 | 原实现 | 改后 | 为什么 |
|---|---|---|---|
| **位移剖面** | `(1-t)²`，位移沿整条带摊开 | **`circleMap`**：半带处位移只剩 13%（原来还有 25%） | 二次剖面下边缘只是一条略弯的带，读不出"透镜"；circleMap 把位移压进贴边薄层，形成苹果那条**细而亮的压缩镜面环** |
| **位移方向** | 从中心指向该点的**径向** | **圆角矩形 SDF 解析梯度**（表面外法线） | dock 是 340×62 的长条，长边中点的径向是斜的 → 折射斜着拐向角落；法线才物理正确。通栏预览条（radius=0）更明显 |
| **采样区** | 只读 footprint 本身 | **外扩 pad**（`ceil(strength)+1`），warp 收 `(ox,oy)` | 向外折射要采 footprint **外面**的内容。原来出界全 clamp 到自身边界 → 边缘一圈拖影。这是原实现最实的一处 bug |

配套：折射强度 6→10dp（dock/floatingBar）、5→8dp（tabPill/hud）。circleMap 下位移集中在
贴边 1~2px，6dp 在真机上几乎读不出。

### 7.3 从 QWEA0 借的

- **色散默认 0.10**（它文档明确给了 `dispersionStrength` 默认 0.10、超过 0.25 读作彩虹）。
  我们原来是 0.35 —— 太重，灰阶底上读作彩色噪点。
- **vibrancy**：模糊后在线性空间抬饱和度。`glass_saturation` = 1.15，sRGB↔线性用
  256 项 LUT（逐像素 `pow` 要 12 万次，查表整张亚毫秒）。灰阶 UI 上不可见，
  压在照片上才显出来 —— 这就是"玻璃比毛玻璃贵"的那一点。
- 它的 `(1+x/k)^-p` 剖面（p=2）与 circleMap 是同族曲线，circleMap 更锐，取了后者。

### 7.4 ⚠️ 一处产品决定被推翻（需要你知情）

**色散从默认关改成默认开**。PRD §3.7 / Q1 原决定默认关，理由是"色散是彩色，
与 `colors.xml:39` 灰阶规范冲突"。重新核对后这个理由站不住：灰阶规范管的是
**UI 状态色**（图标/文字/指示器不许带颜色），色散是**光学伪影**，颜色来自被透射的内容
本身 —— 跟"彩色只允许从被透射的内容里来"不冲突。

回退方式（二选一）：
- 运行时：`UiFlags.set(context, UiFlags.DISPERSION, false)`（设置页加个开关也行）
- 编译期：`UiFlags.DEFAULTS` 里 `DISPERSION to false`
