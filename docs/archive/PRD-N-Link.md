## 1. 产品概述

### 1.1 产品名称

**N-Link**（暂定，最终名称待商标检索确认）

### 1.2 产品定位

一款以「永不断联」为核心卖点的尼康相机移动端伴侣应用，为尼康 Z 系列微单用户提供稳定、高效、全功能的无线连接体验。

### 1.3 目标用户

| 用户画像 | 描述 |
|---------|------|
| 核心用户 | 尼康 Z 系列微单用户（Z50II、Z6III、Z8、Z9、Zf 等 2022 年后机型） |
| 使用场景 | 外拍即时传图、远程遥控拍摄、视频监看、日常随拍自动备份 |
| 技术水平 | 中级及以上摄影爱好者 / 职业摄影师 |
| 设备环境 | Android 10+ 手机/平板，支持 BLE 5.0 及 WiFi 5GHz |

### 1.4 核心痛点分析

同类连接工具频繁断联的根本原因：

| 问题 | 根因分析 |
|------|---------|
| Android 后台杀进程 | 部分相机连接工具未正确使用 Foreground Service，系统 Doze 模式下被回收 |
| BLE 连接管理缺陷 | 未处理 Android BLE 栈的 bond 状态丢失、GATT 连接超时等边界情况 |
| WiFi 切换逻辑脆弱 | BLE→WiFi 通道升级时缺乏状态机管理，切换失败后无回退机制 |
| 重连策略缺失 | 断联后依赖用户手动操作，无自动指数退避重连 |
| 厂商适配不足 | 未针对小米/华为/OPPO 等厂商的激进后台策略做特殊处理 |

### 1.5 产品核心价值主张

- **稳**：连接恢复 < 3 秒，后台存活率 > 99%
- **快**：WiFi 5GHz 传输速率 > 10MB/s，Live View 延迟 < 200ms
- **全**：照片传输 + 遥控拍摄 + 实时取景 + 参数管理 四合一
- **简**：一次配对，永久连接，零操作自动恢复

#### 功能描述

| 功能项 | 说明 | 优先级 |
|--------|------|--------|

| 手动浏览下载 | 浏览相机存储卡照片列表，支持缩略图预览，选择性下载 | P0 |

## 3. 连接稳定性设计（核心差异化）

### 3.1 双通道架构

```
┌─────────────────────────────────────────────────┐
│                  N-Link App                    │
├─────────────────────┬───────────────────────────┤
│   BLE 5.0 通道      │      WiFi 通道             │
│   (常驻心跳)        │    (高速数据)              │
├─────────────────────┼───────────────────────────┤
│ • 设备发现/配对     │ • 照片传输                 │
│ • 心跳保活(5s/次)   │ • Live View 视频流         │
│ • 新文件通知        │ • 遥控指令                 │
│ • 连接状态同步      │ • 参数读写                 │
│ • WiFi 通道唤醒     │ • 大容量数据交换           │
└─────────────────────┴───────────────────────────┘
```

**设计原则**：BLE 通道永远在线（低功耗），WiFi 通道按需唤醒（高带宽）。

### 3.2 Android 保活策略

| 策略 | 实现方式 |
|------|---------|
| 前台服务 | Foreground Service + 持久通知（显示连接状态） |
| WakeLock | PARTIAL_WAKE_LOCK 保持 CPU 运行（BLE 心跳期间） |
| 电池优化白名单 | 首次启动引导用户关闭电池优化（REQUEST_IGNORE_BATTERY_OPTIMIZATIONS） |
| 厂商适配 | 针对小米(自启动管理)、华为(后台保护)、OPPO(后台冻结)提供引导 |
| WorkManager | 周期性连接健康检查（15min 间隔） |
| 开机自启 | BOOT_COMPLETED 广播接收，开机后自动恢复连接 |

### 3.3 智能重连策略

```
断联检测 → 立即重连(0s) → 失败 → 1s后重试 → 失败 → 2s后重试 → 
失败 → 4s后重试 → ... → 最大间隔30s → 持续重试(不放弃)
```

- **指数退避**：初始 1s，倍增因子 2，上限 30s
- **网络感知**：监听 ConnectivityManager，WiFi 恢复时立即触发重连
- **BLE 优先恢复**：WiFi 断开时先恢复 BLE，再通过 BLE 唤醒 WiFi
- **状态机管理**：Disconnected → Connecting → BLE_Connected → WiFi_Upgrading → Fully_Connected

### 3.4 连接状态可视化

- 通知栏常驻：显示连接状态图标（BLE/WiFi 分别指示）
- App 内仪表盘：
  - BLE 信号强度（RSSI）
  - WiFi 信号强度
  - 最后心跳时间
  - 当前通道状态（仅BLE / BLE+WiFi）
  - 连接持续时长
- 断联预警：心跳超时 10s 时震动提醒 + 状态栏变色

### 3.5 断联自动恢复

| 场景 | 恢复策略 |
|------|---------|
| WiFi 断开，BLE 正常 | 通过 BLE 发送 WiFi 重连指令，3s 内恢复 |
| BLE 断开，WiFi 正常 | 后台自动重新扫描 BLE 并配对 |
| 双通道均断开 | 进入全量重连流程（指数退避） |
| 相机关机 | 检测关机信号，进入低功耗等待模式，相机开机后自动恢复 |
| App 被杀 | 前台服务自动重启 + BOOT_COMPLETED 兜底 |

## 4. 技术架构

### 4.1 通信协议栈

```
┌────────────────────────────────────┐
│         应用层 (App Features)       │
├────────────────────────────────────┤
│         会话管理层                   │
│   (连接状态机 / 通道调度 / 重连)     │
├──────────────────┬─────────────────┤
│   PTP/IP 协议栈   │  BLE GATT 协议  │
│  (命令/数据/事件)  │  (心跳/通知/控制)│
├──────────────────┼─────────────────┤
│   TCP/IP (WiFi)   │   BLE 5.0       │
└──────────────────┴─────────────────┘
```

- **PTP/IP**：基于 ISO 15740 标准，实现命令请求（Command）、数据流（Data）、事件通知（Event）三通道
- **BLE GATT**：自定义 Service/Characteristic 用于心跳、文件通知、WiFi 凭证交换

### 4.2 技术选型

| 层级 | 技术选择 | 理由 |
|------|---------|------|
| 开发语言 | Kotlin | Android 官方首选，协程支持优秀 |
| 最低 API | Android 10 (API 29) | BLE 5.0 完整支持 + 存储权限模型稳定 |
| 架构模式 | MVVM + Clean Architecture | 可测试性强，模块解耦 |
| 异步框架 | Kotlin Coroutines + Flow | 天然适配 BLE 回调流式处理 |
| DI 框架 | Hilt | 官方推荐，编译期验证 |
| 网络层 | 自定义 PTP/IP Socket | 标准 TCP Socket + 自定义协议解析 |
| BLE | Android BluetoothLe API | 原生 GATT 操作 |
| 视频解码 | MediaCodec + OpenGL ES | 硬件加速 H.264/MJPEG 解码渲染 |
| 图片处理 | Coil + 自定义 EXIF 解析 | 高效缩略图加载 |
| 本地存储 | Room + MediaStore | 传输记录 + 照片归档 |
| 后台任务 | WorkManager + ForegroundService | 保活 + 周期任务 |

### 4.3 模块划分

```
app/
├── core/
│   ├── ble/              # BLE 扫描、配对、GATT 通信
│   ├── wifi/             # WiFi Direct/Infrastructure 连接管理
│   ├── ptp/              # PTP/IP 协议栈（编解码、会话管理）
│   ├── connection/       # 连接状态机、通道调度、重连策略
│   └── common/           # 工具类、扩展函数
├── feature/
│   ├── transfer/         # 照片传输模块
│   ├── remote/           # 遥控拍摄模块
│   ├── liveview/         # 实时取景模块
│   ├── settings/         # 参数管理模块
│   └── dashboard/        # 连接状态仪表盘
├── data/
│   ├── repository/       # 数据仓库层
│   └── local/            # Room 数据库、SharedPreferences
└── di/                   # Hilt 依赖注入模块
```

## 5. 非功能需求

### 5.1 性能指标

| 指标 | 目标值 | 测量条件 |
|------|--------|---------|
| 连接恢复时间 | < 3 秒 | 从断联检测到完全恢复（BLE+WiFi） |
| Live View 延迟 | < 200ms | WiFi 5GHz，相机到手机屏幕端到端 |
| 照片传输速率 | > 10MB/s | WiFi 5GHz，24MP JPEG 文件 |
| 后台存活率 | > 99% | Android 12+，主流厂商设备，24h 周期 |
| BLE 心跳功耗 | < 3% 电量/24h | 仅 BLE 通道活跃，屏幕关闭 |
| App 冷启动 | < 2 秒 | 中端设备（骁龙 7 系列） |
| 遥控快门延迟 | < 150ms | 从触屏到相机快门动作 |

### 5.2 兼容性

- Android 10 (API 29) ~ Android 16 (API 36)
- 屏幕：手机（6.1"~7.2"）+ 平板（8"~12.9"）
- 蓝牙：BLE 5.0 及以上
- WiFi：2.4GHz / 5GHz 双频支持

### 5.3 安全性

- BLE 配对采用 Just Works + 应用层校验
- WiFi 通道使用 WPA2/WPA3 加密
- 本地照片存储遵循 Android Scoped Storage
- 不上传任何用户数据至第三方服务器

## 7. 风险与约束

### 7.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 尼康未公开 Mobile SDK | 需逆向 PTP 扩展命令集 | 基于 PTP/IP 标准协议 + 抓包分析 |
| 各厂商后台策略差异 | 部分设备保活失败 | 建立厂商适配矩阵，引导用户手动设置 |
| WiFi Direct 与已连 WiFi 冲突 | Android 10+ 限制同时连接 | 优先使用 Infrastructure 模式（相机作为 AP） |
| Live View 延迟不可控 | 相机编码性能瓶颈 | 自适应分辨率/帧率降级策略 |
| BLE 兼容性碎片化 | 部分手机 BLE 栈不稳定 | 多设备测试矩阵 + 降级重连策略 |

### 7.2 法律合规

- PTP/IP 为 ISO 公开标准，基础协议实现无法律风险
- 尼康私有扩展命令的逆向工程需评估当地法律（个人研究用途通常合规）
- 产品命名/宣传不得暗示尼康官方授权
- 不使用尼康商标/Logo

### 7.3 约束条件

- 初期仅适配 Z50II，验证后再扩展
- 不依赖任何尼康云服务
- 纯本地通信，无网络数据上传
