## 2. 参考结论与差异化建议

> 依据 `docs/CONTRIBUTING.md`「外部产品信息不入库」：本节原先记录的外部产品实机取证、
> 版本级对照对象清单与静态认知已移除。以下保留的是**不依赖具体产品**的行业通识，
> 以及本项目自己的差异化决策 —— 它们是 §3 实施路径的取舍依据，缺了会让后面的
> 「为什么这样收口」失去出处。

### 大厂感共性（行业范式通识，非逐条对照某产品）
1. **一个页面只有一个视觉重心**：首页 = 英雄区 + **一枚**主 CTA；其余全部退到灰阶。强调色全 App 只有一支，出现位置 ≈ 3 类（主按钮/选中态/链接）。
2. **空态是设计组件不是提示文字**：图标容器（72dp 圆角方块）+ 粗标题 + 引导副文案 + 行动按钮；网格 3px 缝隙全出血、无卡片包边。
3. **克制的动效**：只有按压反馈、tab 切换、进度流动三类；时长统一在 150-400ms，曲线一致，无弹跳滥用。
4. **排版层级 ≤5 档**、间距严格 4/8 倍数、卡片圆角统一——"统一"本身就是高级感的来源。
5. **首屏零等待感**：无相机时页面立即完整渲染（英雄图+按钮常驻），数据区才进入加载/空态。

### 我们的差异化（不走深色赛博，走自己的"黑白灰+黄"）
- **浅色工作台路线**：浅色为主、黑白灰+尼康黄，在一众深色相机 App 里反而构成辨识度（走「平面设计式」克制路线而非「产品渲染式」路线）。深色模式按规范同值映射，不另造氛围。
- **强调色纪律更强**：锁死「状态灯 + 主按钮」两处（规范 §1.1），选中态一律黑/白 chip——比常见同类做法更克制，形成自己的签名。
- **玻璃材质是我们的独有资产**：GlassTokens L1/L2/L3 + 运行时降级构成层级语言，dock/顶栏/操作栏三处玻璃即可，不扩大使用面（材质稀缺感 = 高级感）。
- **信息密度专业向**：相机传图工具要"参数可见"（速率/频段/进度环），比通用相册多一层专业仪表感——这是属于我们的差异化。

## 3. 分阶段实施路径（技术栈不变）

### S1 · 设计体系收口（1 周，纯机械化，风险最低收益最大）
**做什么**
- 字号：dimens.xml 建 6 档（`font_display 24 / title 17 / body 14 / caption 13 / foot 11 / nav 12`），182 处 textSize 全量替换 + 顺手消灭 9/10/11sp 野字号（正文最小 11sp）
- 动效：建 `Motion.kt`（DURATION fast/base/slow = 150/220/380ms + EASE_GLASS 曲线，与 GlassMotion 同源），20 个裸 setDuration 收口；PressEffect 补 `UiFlags.motionEnabled` 与系统"移除动画"检查
- 间距：397 处裸 dp 按 4/8/12/16/20/24 栅格归位到 @dimen（脚本辅助 + 人工核对）
- 颜色：layout 内 10 处硬编码色收进 @color 遮罩族；support 页白卡换语义 token（修夜间刺眼）

**产出**：token 渗透率报告（替换清单）、lint 规则（硬编码 textSize/dp 报警）、全 App 视觉回归截图基线
**验收钩子**：见 §4 指标 1-3

### S2 · 三态与反馈组件（1 周）
**做什么**
- `NlEmptyState` 自定义 View（图标容器 + 标题 + 副文案 + 行动按钮），替换 DashboardFragment.emptyHint() 等代码拼字
- `NlStateBar` 内联错误条（图标 + 一句话 + 重试按钮），拍摄页/监看页接入——错误不再只靠 Toast
- 相册/首页列表接入**骨架屏**（shimmer，形状用现有 bg_chip 灰阶，不引入新库，~80 行 drawable+动画）
- 触达治理：66 处 <44dp 目标抬到 48dp（chip 高度 + padding 补足）；38 个无反馈点击统一 pressEffect()
- Snackbar 升级：复用 NlFeedback，加 TalkBack liveRegion 语义

**产出**：三态组件库（demo 页挂在设置→关于→"组件预览"）、四大页三态全覆盖矩阵
**验收钩子**：§4 指标 4-6

### S3 · 组件化与代码规范（2 周，与 S2 可并行）
**做什么**
- 首页拆分：fragment_dashboard.xml（1173 行/10 层）→ include 子布局（connect_hero / device_card / quick_grid）+ 局部 ConstraintLayout 降层级；DashboardFragment 渲染逻辑抽 ViewRenderer
- 监看页横竖屏共用 HUD include（消掉 990 行复制树）
- 文案抽离：439 处中文硬编码分批进 strings.xml（先四大页，后长尾）
- 代码规范落 docs：新增 UI 代码强制走 Nl* 样式 + Motion token（写进 CLAUDE.md/PR 模板 checklist）
- 删除零引用 Coil 依赖

**产出**：首页布局 ≤600 行/≤6 层、组件预览页、UI 规范 checklist
**验收钩子**：§4 指标 7-8

### S4 · 渲染性能与包体（1 周）
**做什么**
- 基线测量先行：`adb shell am start -W` 冷启动、`dumpsys gfxinfo` 相册 fling 帧率、Layout Inspector 层级——先有数字再动手
- 相册网格：网格项去 overflow 裁剪、GoneInvisible 处理、fling 时 ThumbnailCache 请求优先级已有——补预解码尺寸与 view 复用校准
- 启动路径：MainActivity→Dashboard 首帧依赖审计（bleManager/wifiManager start 延后到首帧后）
- 包体：release 4.1MB 保持 ≤4.2MB 红线；删 Coil 后核对；资源全矢量已达标（唯一位图 132KB 捐赠码可改 WebP）

**产出**：性能基线报告（改前/改后两张表）、包体看板（CI 打印 apk size）
**验收钩子**：§4 指标 9-11

### S5 · 缓存与线上监控（1 周搭好，长期运行）
**做什么**
- 崩溃/ANR 采集：本地 crash.log 已有，补启动耗时、慢帧计数进 FR-08d 导出物（指标基线扩展「UI 段」）
- 图片缓存命中率打点（ThumbnailCache 已有 LRU，补 hit/miss 计数）
- 每周发版带 UI 回归：真机截图 × 4 页 × 双主题归档到 docs/（延续本项目"一手取证"的既有习惯）
- 建立视觉回归人工流程：改 token → 跑四页截图 diff → 归档

**产出**：导出物新增 UI 指标段、截图归档目录、发布 checklist

## 附：刻意不做的事

- **不引入 Compose / 不换图片库**：自研 ThumbnailCache 质量高于平均水准（LRU+磁盘+降采样+fling 暂停），迁移是风险不是收益
- **不推翻黑白灰+黄**：这是 v2.6.5 已拍板的品牌决策，本方案所有设计结论都在强化它而非替代它
- **不做全 App 大重排**：已真机验收的布局不动，质感提升走 token 渗透 + 三态 + 微交互三条线
- **不上移动端埋点 SDK**：与「无云端依赖」卖点冲突，UI 指标走既有 FR-08d 本地导出物
