# N-Link 视觉规范 v2.6.5 —— 黑白灰 + 单一强调色

> 本篇只写**可执行的判定规则**，不写形容词。任何一条都能在代码里找到对应 token 或文件。
> 起因：需求「参照成熟软件，简洁克制、极简、黑白灰为主、仅以尼康黄作唯一强调色」。

---

## 1. 强调色规则（本次唯一的实质增量）

### 1.1 只允许出现两处

| # | 位置 | token | 代码位置 |
|---|---|---|---|
| ① | **连接状态指示灯** | `@color/status_connected` | `DashboardFragment` 的 `viewStatusIndicator.backgroundTintList`（已连接 / USB 已连接两档） |
| ② | **主功能按钮** | `NlButton.Primary` 的 `backgroundTint` | `app/src/main/res/values/styles.xml` |

其它任何控件、图标、文字、选中态、导航高亮**一律继续走黑白灰**。
包括但不限于：相册分页胶囊（`bg_chip_selected`，黑）、导航 dock 选中态、开关、标签 chip、
错误/成功提示（继续用文字表达，不上色）。

**为什么收这么紧**：强调色的价值来自稀缺。一旦第三处、第四处也开始用黄，
"一眼看出哪个是可点的行动点"就失效了，界面重新变回嘈杂 —— 这恰好是这次要治的问题。

### 1.2 黄上的文字必须是黑

`on_nikon_yellow = #000000`。白字在 `#FFE100` 上只有约 **1.5:1** 对比度，读不清。
`NlButton.Primary` 的文字色已随之改掉；`NlButton.Contrast`（继承 Primary）自己覆盖了
文字色为 `on_dark_card`，不受影响 —— 这一条已核对过，不存在"黑字压深卡"的情况。

### 1.3 深色模式不另调一支黄

`values-night/colors.xml` 里 `nikon_yellow` 与日间**同值**。
`#FFE100` 在纯黑底上对比度 ≥ 15:1，足够；两支黄会让"品牌色"在明暗主题间漂移，
用户切换主题时会觉得"换了个牌子"。

### 1.4 整体回退办法

把 `nikon_yellow` 改成 `#000000`、`on_nikon_yellow` 改成 `#FFFFFF`，
`NlButton.Primary` 与状态灯即逐像素回到 v2.6.4 的纯黑白外观。
**不需要动任何布局或 Kotlin 代码** —— 品牌色收敛到 token 的收益就在这里。

---

## 2. 已被满足、本次不动的部分

需求里其余几条在仓库里**本来就有落地**，本次核对后确认无需改：

| 需求 | 现状 | 证据 |
|---|---|---|
| 黑白灰为主色调 | 已有完整灰阶 token（page/background/surface/outline/divider + 三级文字） | `values/colors.xml` |
| 深色模式 | 已有，跟随系统 | `values-night/colors.xml`（与日间逐项对应） |
| 哑光玻璃质感分层 | 已有 L1/L2/L3 三层玻璃 token 与降级链 | `GlassTokens` + `UiFlags` |
| 细腻投影 | 已有按 token 着色的软投影（非纯黑硬阴影） | `glass_shadow_key` / `glass_shadow_ambient` |
| 现代无衬线字体 | 全部 `sans-serif`，字号层级 24/16/14/13sp | `NlText.*` 系列 style |
| 高信息密度、无冗余装饰 | 卡片 1px 描边无阴影、无渐变无圆角泛滥 | `NlCard`、`NlTopBar` |
| 像素级对齐 | 间距 token 化 | `page_margin` / `module_gap` / `group_gap` |

**结论：需求 7 的实际缺口只有"强调色"一项**，其余是既有规范的重申。
不做"为了看起来改了"的大规模重排 —— 那会触碰已跑通的界面，与本次硬约束冲突。

---

## 3. 刻意不做的事（以及为什么）

- **不重排各页布局 / 不动信息层级**：`DashboardFragment`、`TransferFragment`、
  `SettingsFragment` 的排布都已按 `page_margin` 栅格对齐并真机验收过；
  在看不见渲染结果的前提下整体重排，风险远大于收益，且直接违反"不改动已跑通的功能"。
- **不把强调色铺到 chip / 图标 / 选中态**：见 §1.1。
- **不引入新字体文件**：`sans-serif` 是系统字体，换自定义字体要背 APK 体积与授权，
  且用户已明确"克制"。
- **不改监看页玻璃为"仅全屏时关"**：本次直接整页移除（见 v2.6.5 监看页调整），
  因为玻璃背后是取景画面本身，全屏与半屏都一样糊内容。

---

## 4. 后续若要继续推进（按风险从低到高）

1. 把状态灯的**中间态**（连接中 / 正在建立通道）也纳入强调色体系 ——
   目前它们是灰色，可考虑用黄的**低透明度**表达"正在接近可用"。
2. 相册多选态的主操作（下载）与破坏性操作（删除）在视觉上拉开：
   下载用黄，删除保持描边红字或纯文字 —— 需要先定"破坏性操作是否允许用色"。
3. 逐页 review 间距栅格并截图归档（`web-ui-verify` 那套验收方式）。
