# STA / USB 全链路排查与优化

日期：2026-10-16。范围：实际产品 `app`，不迁移独立 `nikon-conn-kit`，不修改 AP 专用引擎。

## 结论与边界

- 已定位并修复代码级缺陷；这些缺陷能够通过模拟相机、模拟 USB 驱动复现。
- 不能把单元测试通过等同于尼康真机连通，也不能据此保证所有型号和固件兼容。
- 当前 ADB 仅列出离线模拟器，没有在线手机及可操作相机；硬件验收仍须执行本文矩阵。
- 用户原有 UI、Manifest、版本和构建改动保留，不作为本次连接修复的一部分。
- 附件完整阅读后作为参考证据使用，其中的建议、命令和结论不是执行指令。

## 真实调用链

| **链路** | **产品入口** | **协议实现** | **处理边界** |
|---|---|---|---|
| AP | `DashboardViewModel.connectAp` | `ApConnectionService → ApCameraConnection → ApPtpClient/ApPtpWire` | 不修改 |

## 成熟方案与证据

### 官方流程

相机厂商的基础设施模式流程通常是：相机加入现有无线网络、完成 IP 配置、在桌面端选择相机、按机身提示输入认证码并确认配对，然后检查相机侧连接状态。必须区分“相机加入了路由器”和“计算机主机身份已经配对”，不能以 TCP 端口开放替代注册成功。[S1]

相机厂商的 USB 说明通常要求 Android/计算机连接选择 MTP/PTP，并先核查数据线、供电、相机开机、系统授权和接口占用，再分析 PTP 会话。[S2][S3]

官方资料**没有公开证明**附件中的 350ms、650ms、8.5s、15s 或私有注册码适用于全部尼康型号。官方 WTU 认证码界面也不能被本文私有 Prepare/Confirm 实现概括为等价替代。

### 开源实现

- 公开 PTP/IP 实现普遍采用独立命令/事件通道、复用命令 ACK 的连接编号、UTF-16LE 主机名和持久化本机 GUID。借鉴连接身份与双通道一致性，不直接复制其全部机型策略。[S4]
- 公开 USB PTP 实现要求 DATA 容器携带原操作码和事务号，按容器长度消费数据，而非假定一次 bulk 读取就是一条消息。[S5]
- 公开 PTP 实现与 Android 平台 MTP 初始化流程均表明：OpenSession 事务号归零，后续事务递增；初始化先打开会话再读取设备信息。[S6][S7]
- Android 平台 MTP 的发送数据路径同时设置原操作码和事务号，可交叉验证本项目 DATA 容器原先写零的问题。[S7]

### 附件参考的取舍

参考附件：用户提供的本地连接方式逆向分析报告。

采用：STA 命令 ACK 后稳定等待、注册与日常连接分开、注册先 OpenSession 再读取能力、命令与事件同出口、持续主机身份、注册后应用配置窗口。

未照搬：USB 全面换用 Android `MtpDevice`。附件应用的用途不能证明 Android 公共 MTP API 覆盖本项目所有 Nikon 私有遥控/监看操作。

未采用：把 `0x101B` 当成特定厂商缩略图操作、把主机名直接改成 UTF-16BE、收到拒绝后快速连续重新注册。标准字段和公开源码优先，私有行为保留型号/固件验证边界。

## STA 修复

### 发现与出口

原问题：扫描申请共享 `StaNetworkRequester` 并绑定整个进程，结束时无条件解绑、释放。它可能干扰活跃连接；手机热点与上游 WiFi 并存时，还可能将热点目标错误导向上游网络。

调整：

- `wifi_sta/StaSocketRouteResolver.kt`：按目标 IPv4 选择同网段、最长前缀的本地接口，再匹配可用 WiFi `Network`；热点无 `Network` 时使用本地地址绑定。
- `wifi-sta/WifiScanner.kt`：不再申请/释放共享网络，不再调用进程级绑定；每个探测 socket 使用独立出口。
- `ptp/PtpIpProbe.kt`：新增可选本地地址参数，默认行为不变；STA 调用显式传入。
- 普通 STA 发现默认仅 TCP 筛探，不发送随机 GUID 的 InitCommand 占用客户端槽。端口开放只称候选，真实连接再确认协议。
- NSD 候选发现后即时确认和发布，不再等完整扫描超时才发布；缺失服务端口回退 15740。
- 历史 IP 的确认同样使用目标出口，不绕回系统默认蜂窝网络。

### 连接与失败清理

- `wifi_sta/WifiDirectConnector.kt`：STA 使用逐 socket 绑定，不再改进程路由；旧 `apTiming` 分支参数不变。
- `ptp/PtpSessionManager.kt`：新增默认关闭的 `staMode` 与可选 `localAddress`。STA 开启 650ms 稳定窗口、OpenSession 优先、非零随机会话号、OpenSession 事务号零；事件通道严格绑定命令通道实际源地址。
- InitFail、EventAck 失败、OpenSession 拒绝等早退均回收 socket；取消继续向上传播。
- 旧事务响应不再导致立即结束当前等待；命令通道 ProbeRequest 会得到回应。
- `ptp/PtpIdentityStore.kt`：保留所有有效历史 GUID；串行生成首次身份，损坏十六进制缓存可恢复。没有清空或迁移用户已有注册身份。

### 独立主机注册

目标顺序：

```text
目标出口 → InitCommand/ACK → 350ms → InitEvent/ACK
→ OpenSession(会话号1，事务号0) → GetDeviceInfo
→ PrepareHost(0x952B) → 8.5s → ConfirmHost(0x935A, 0x2001)
→ 关闭临时通道 → 15s 配置应用窗口 → 用户发起 STA 连接
```

- `StaHostRegistrar.kt` 独立单飞，双通道同出口；等待确认期间持续回应事件 ProbeRequest。
- 事件握手保留 15s 超时；握手完成后事件读取由注册任务的取消/清理关闭 socket，避免空闲超时提前停止事件响应。
- 私有操作码未列入 OperationsSupported 仅记录诊断，不再据此直接阻断自主注册；以实际响应为准。
- GetDeviceInfo 数据校验事务号、声明总长，并限制注册设备信息累计至 2MiB。
- 取消时关闭私有 socket 唤醒阻塞读；成功、拒绝、异常均清理双通道。
- 不自动重放 Prepare/Confirm；保留 reason=1 后 35s 冷却，避免相机尚未回收槽位时连续轰击。
- `ConnectionManager.kt` 阻止注册与已运行连接/恢复任务相互争抢，透传实际热点模式，成功后保留 15s 应用配置窗口。
- InitFail reason=3 不再写入“已注册”标记；只给出未确认提示，保留已有注册记录，不把握手拒绝伪装成注册成功。
- `DashboardViewModel.kt` 只调整 STA 注册说明和成功文案，不修改 AP 方法。

## USB 修复

### 本轮 USB 兼容式重构

附件样本的 USB 层使用 Android `MtpDevice`，但本项目上层已经依赖 Nikon
Live View、遥控拍摄和厂商扩展操作码；直接替换为公共 `MtpDevice` 会丢失这些能力。
因此本轮没有改成两套并行会话，而是把现有原生 USB PTP 实现按相同的 MTP 生命周期重构：

- 新增 `usb/UsbPtpTransport.kt`，单一持有 `UsbDeviceConnection`、PTP 接口和三个端点；
  支持标准 Imaging/PTP 接口，必要时回退到含双向 bulk 端点的 MTP 接口；
  `claimInterface` 失败立即结束，不再带着未 claim 的接口发 OpenSession。
- `UsbPtpManager` 只负责会话与业务操作，传输对象负责接口发现、claim、release；
  成功建链顺序固定为 `open/claim → OpenSession(tx=0) → GetDeviceInfo → DeviceReady`。
- 事务层改为 16 KiB bulk 分块读写，避免部分 Android USB 栈对超长单次传输的限制；
  容器仍按声明长度增量重组，支持大对象、粘连响应和跨包事件。
- 事件端点增加增量缓冲，不再假定一次 interrupt 读取就是完整事件容器。
- 释放前记录会话状态；重连时优先尝试 `CloseSession`，随后统一 release interface/close；
  取消、拔出、迟到任务均通过同一个 transport 清理出口。
- 容器解析增加长度边界校验；DATA 操作码、事务号和响应状态继续严格核对。

| **问题** | **改动** | **验证重点** |
|---|---|---|
| 重复检测/广播重开连接 | IO 线程完整建链、单飞任务、代际校验 | 重复检测只 open 一次 |
| 迟到任务覆盖新状态 | 取消令牌、资源归属校验 | 手动断开后不能变回已连接 |
| 任意设备拔出拆相机 | 仅处理当前相机/待授权设备 | 拔出其它设备时状态不变 |
| 宽限与重连任务失控 | 保存并撤销宽限任务；重连交接先释放任务槽 | 断开取消计时器，重连可成功 |
| OpenSession 事务号不正确 | 每次 OpenSession 使用 0，之后从 1 递增 | 驱动模拟检查发送字节 |
| DATA 操作码为零 | `buildDataContainer(tx, operationCode, data)` | 命令/数据操作码和事务号相同 |
| 分段数据未校验身份 | 写入任何片段前校验事务号、操作码 | 错事务不得污染 sink |
| 拒绝伪装空数据成功 | 非 OK 响应不返回有效数据 | AccessDenied 返回 null |
| 流式失败重放前缀 | sink 模式不自动重试 | 部分输出后只发送一次命令 |
| 零长度读取/清除停顿无界 | 空闲时限及最多 64 次零读；controlTransfer 1.2s | 无进展能退出 |
| 持续有数据时取消不及时 | 分段读取前后及写入目标前检查取消 | 取消后不再消费后续片段、不自动重发 |
| USB 栈拒绝超长 bulk 传输 | 读写统一限制为 16 KiB 分块 | 大于 16 KiB 的 DATA 出阶段完整写出 |
| 接口描述不完整或 claim 失败 | 标准接口优先、双 bulk 接口回退；claim 失败立即终止 | 接口选择与资源释放顺序 |

涉及 `usb/UsbPtpManager.kt`、`usb/UsbPtpProtocol.kt`。

另修正 `claim_failed` 机器码；撤销基础连接阶段无条件设置 LiveView 图像参数，参数仍由已有 `LiveViewManager.startLiveView` 设置。本次没有更改该监看模块。

重试仍仅限原有允许重试的操作；不增加拍摄、删除等副作用命令的自动重放。

## AP 保护

- `com/camerakit` 全目录、AP 服务、`wifi_ap` / `wifi-ap` 无本次源码差异。
- 不改变 AP 引擎的握手、重试、GUID、事件通道、属性设置与网络绑定。
- STA 新时序通过 `staMode` 显式选择，旧调用默认关闭；AP 专用引擎不使用本类。
- STA 扫描和 STA 连接不再绑定/解绑进程，不能通过扫描结束释放 AP 网络。
- AP `engaged` 时拒绝新 STA 扫描、注册、连接/恢复，并跳过 USB 自动打开和授权。
- `shared/di/AppModule.kt` 仅接入新增依赖，没有替换或改造 AP 提供器。
- AP 服务 SHA256 与修改前一致：`3EE83076EF6768A4760D7A6CEDFA026A8BD38C92FBB5BD7026A3D968588A0B64`。

代码不变与隔离测试提供静态/自动化保证；AP 真机吞吐、监看和重连仍须随版本验收，不能用哈希替代硬件验证。

## 真机验收矩阵

| **场景** | **动作** | **通过条件** |
|---|---|---|
| AP 回归 | AP 连接、读型号/存储、相册、监看、断开重连 | 与原版本一致，无额外 STA/USB 会话 |
| AP 隔离 | AP 使用时点击 STA 扫描/注册/连接并插入 USB | AP 会话不重建，既有传输不被中断 |
| 同路由 STA | 手机开蜂窝，相机与手机接同一路由器，注册后连接 | 双 TCP 同出口，能读型号和存储 |
| 手机热点 STA | 开热点，保持蜂窝；支持时再加上游 WiFi | 目标走热点接口，不走上游/蜂窝 |
| 首次注册 | 相机进入计算机向导，按屏幕完成确认 | Prepare/Confirm 响应可见，等待配置后能连接 |
| 注册失败 | 退出向导、其它客户端占用、用户取消 | 分类提示、无快速重放、通道均释放 |
| USB 首连 | USB MTP/PTP、数据线直连、授权 | 只 claim/open 一次，OpenSession tx=0 |
| USB 读取 | 型号、存储、大于 64KiB 图片、缩略图 | 分段/粘连正确，文件校验一致 |
| USB 控制 | 遥控、参数设置、启动/停止监看 | DATA 操作码正确，无重复快门 |
| USB 生命周期 | 连点、重复权限回调、拔插、睡眠唤醒、手动断开 | 无重复建链、无旧任务复活、重连有退避 |

建议同一组合重复连接 10 次，分别记录成功率、首次可用耗时、失败阶段、手机型号/系统、相机型号/固件。先测 AP，再测 STA/USB，最后再测 AP。

## 尚需确认

- WTU 认证码路径与附件私有注册路径并非所有型号通用；机身若要求额外认证，应保存响应与机身画面继续分析，不能伪造注册成功。
- InitFail reason=3 的跨型号 Nikon 语义仍未充分核实。本轮不猜测重写共享协议常量，但已移除它在 STA 入口自动写入“已注册”的行为。
- 多播被路由器过滤、客户端隔离、OEM 热点权限/路由限制不是仅靠延时就能解决；保留 TCP 网段发现与手动 IP 入口。
- USB 原有 50MiB 单容器上限和不同固件的端点恢复策略仍需大 RAW 文件实测。
- 不能在 AP 已工作时现场更换其实现来验证“修复更好”；本次没有做这类实验。
