## 一、v2.7 的核心目标与主题定位

### 1.1 主题

> **「从能连，到可信」——把稳定性变成看得见、能复现、能被外人验证的东西。**

选这个主题的依据不是"我们觉得该补基建"，而是竞品分析 §7 的结论句：

> **【推】下一个 3 个月，谁的「可证明的稳定」跑出来，谁就拿走这条赛道的话语权。**

以及 §7.2 的时间约束：能力面最完整的付费对手 **Android 版正在内测**【待核·用】，我们原本
"Android 平台独占"的独占位**剩余窗口以周计**。同时 §5.3 点名我们的三个结构性劣势里，
第三个正是：

> **工程质量基建比竞品薄**：无 CI、无 instrumented 测试、无崩溃上报、无英文、兼容矩阵 19 条中
> 9 条从未真机验证、**仓库无 LICENSE**。我们对外说「开源可信」，但**可信性的基础设施本身有洞**。

而 v2.6 PRD §13.4 的审计结论给了另一半依据：

> **17 项 v2.5 FR 里 0 项达到 L3**（真机矩阵 + 回归）。「**M0 先建立可复现的真机回归脚本**」至今
> 零实现（仓内无 `.sh`/`.ps1`，`tools/` 只有两个 Python 探针）——**这一条不补，后面每一项都
> 只能停在 L1/L2**。

两处独立来源指向同一件事：**我们有功能，但没有证据；而对手正在把证据变成信任凭证
（4.6→4.7 分、逐版 changelog）**。这不是能靠再堆一个功能追上的差距。

### 1.2 三个目标（不再增加）

| # | 目标 | 一句话 | 为什么是它 | 不做到会怎样 |
|---|---|---|---|---|
| **G1** | **可证明**：把稳定性从"感觉变好了"变成"有数字、能复现" | 真机回归脚本落地 + 三项基线采到第一份可信样本 + CI + LICENSE | 它是 **L2→L3 唯一那道门**，也是对外唯一能拿得出手的信任凭证 | 后面每做一项都只能停在 L1，且"我们更快更稳"这句话在外部**不可验证** |
| **G2** | **可照做**：把"连不上"从笼统原因码变成用户下一步能做的动作 | 失败原因分级 + 可操作文案 + 深链落点 + 冷却/降频不硬停手 | 最高频差评面。竞品已把拒绝原因拆到 `期望 InitCommandAck，实际包类型=0x` 这一级；我们仍停在 `camera_unreachable`【实】 | 用户只会得到"连不上"，然后卸载；群友日志里 gen=1→8 同条件空转仍在发生 |
| **G3** | **差异化**：补一条"只有我们能做、对手唯一、成本极低"的能力 | GAP-27 写侧 `0x101A`：相机端标记 → 只传被标记的 | 竞品分析原文称其为**「本次分析里性价比最高的一条」**：不需要私有命令、不需要云端、不需要后台常驻 | 我们继续停留在"全量下载"，而 P1（婚礼/活动摄影师）的真实动作是"在现场挑几张" |

**为什么 G1/G2 排在 G3 前面**：G3 是功能，G1/G2 是"能不能证明 G3 真的可用"。在窗口以周计的
前提下，先立证据、再补功能。

### 1.3 主题之外，本版不碰的事（一句话版）

不新增监看工具、不做包围曝光、不扩多品牌、不做多语言、不做付费。**理由见 §7。**

## 三、竞品压力：对手强在哪，我们怎么接

> 全部结论来自 `docs/竞品分析-2026Q3.md`（版本基准 v2.3.1，复核至 **2026-10-01**：§7.1 = 09-24、§7.2 = 09-29、§7.3 = 10-01）与三份
> `.tmp` 连接诊断。此处只保留**会影响 v2.7 排期**的部分。

### 3.1 对手的三类优势

| 维度 | 对手优势（带证据） | 我们的差距【实】 |
|---|---|---|
| **功能** | 监看工具整套（LUT / 斑马 / 峰值 / 波形 / 安全区）被做成 ¥148 买断档的付费理由【官】；**「相机端标记保护 → 只传被标记的」只有一家有**【官】；1:N 群组、无卡拍摄【官】 | 监看工具全仓 0 命中（伪彩/RGB 波形已写但闸门默认关、未真机验）；`0x101A` 写侧全仓 0 命中；读侧已做 |
| **体验** | 错误原因拆到包类型/GUID 级（`PTP_GUID_REJECTED`、`期望 InitCommandAck，实际包类型=0x`）；对拒答**立即放弃 + 冷却**，不做无意义重试；**每次重试换条件** | 我们 `camera_unreachable` 一个码盖全部；Z8 诊断日志里 gen=1→8 每次同一 `fail_reason=1`，"纯属空转" |
| **性能** | 对手**有可引用的公开指标**：帧率自适应、自述指标行「预览 %.1f FPS，最大卡顿 %d ms」；分块按实测吞吐自动选档 | 我们 **15fps 硬编码 66ms**、CPU 解码 + ImageView 上屏；**无 p50/p95、无首连成功率、无崩溃率**（GAP-09 零量化基线） |
| **可信性** | 商店评分 4.6→4.7（55→70 评，4 天 +13）、逐版 changelog【官】 | 我们的节奏"变成提交记录和网盘文件，**普通用户看不见也验证不了**" |

### 3.2 三条应对策略（对应 G1/G2/G3）

| 对手优势 | 我们的应对 | 落到 v2.7 的哪一条 |
|---|---|---|
| **对手把节奏兑换成商店评分与 changelog** | 不追商店，追**可验证**：把基线、真机矩阵、CI 变成 GitHub 上任何人能看到的证据；补 LICENSE 让"开源可信"在法务上成立 | **G1**（R1b 脚本 / 基线首份样本 / CI / LICENSE / R1d 机型验证） |
| **对手把失败原因拆到包类型级** | 我们不需要拆到那么细，但要拆到**用户能照做**：把 `camera_unreachable` 拆成"地址不可达 / TCP 超时 / 机身未认可此主机（去注册）/ 连接位被占用（去腾挪）/ 权限被拒"，每条配文案 + 深链；同时把"8 轮停手"改降频、"占用窗口内立即冷却" | **G2**（R2b 映射纠正 / 文案分级 / 冷却-降频 / 深链） |
| **对手唯一独有的「标记→选择性传图」** | 直接补齐写侧 `0x101A`：把"我要传哪几张"从手机侧搬到相机侧，正好是摄影师现场的真实动作 | **G3** |

### 3.3 我们有而对手没有、且 v2.7 该拿去说事的

- **尼康 BLE 私有配对的 Android 原生实现**（`BleManager` + `NikonBlowfish`）—— 竞品分析称其为
  **「全行业（含全部开源项目）唯一」**【实】。
- **BLE + WiFi(AP/STA) + USB 三通道全打通 + 统一诊断**（12 Stage / 40 Reason + 9 项预检）——
  "三家各缺一角，我们全有"。
- **「检测到占用 → 一键引导腾挪」**——竞品全无，是把官方互斥约束转成好评点的唯一动作
  （S6 场景，FR-07 已落分类，引导闭环待补）。
- **HyperOS 适配**——「目前**没有任何竞品处理** HyperOS」，是空白差异化点。

> ⚠ 前两条的有效期已被竞品分析 §5.3 警告：**"Android 上只有我们把尼康私有配对做穿了"这句话
> 必须按季度复核**。付费对手的 Android 版是否含 BLE 配对，是**决定我们窗口长度的第一待核项**（§8）。

## 四、候选需求池与 P0 / P1 / P2 排序

### 4.1 排序依据（四维，逐项打分）

| 维度 | 打分口径 |
|---|---|
| **用户价值** | 落到 **v3.0 §〇** 画像 P1–P4 与场景 S1–S6 的哪一行（原 §1.4 已随 v2.6 归档，10-03 在 v3.0 重建）；指不到任何一行的，按铁律不进本版 |
| **商业价值** | 对"获客 / 留存 / 口碑 / 可信性"的贡献（本期不含变现，§1.3 已裁定付费非目标） |
| **实现成本** | 沿用 v2.6 PRD 的容量档：S ≈ 0.5 人日 / M ≈ 1.5 人日 / L ≈ 4 人日 |
| **依赖与风险** | 是否依赖未回填的真机数据、是否触碰 A 层禁区（`PtpSessionManager` / 状态机） |

**硬排序规则（来自上游，不是我新定的）**：
1. R1b（真机回归脚本）不补，其余每一项做完**也只能停在 L1** → 它是 G1 的第一顺位。
2. 依赖未回填数据的判据改动**一律后置**（R2 组）。
3. 影响"能不能连上、能不能传完"的在前；纯观感在后。

### 4.5 G2 的落地清单（P0-5 展开，可直接照做）

文案分级表（沿用 STA 诊断 P2 的建议值，非竞品原文）：

| 触发条件 | 用户看到的话 | 附带的动作 |
|---|---|---|
| `fail_reason=1`（机身未认可此主机） | 相机还没认可这部手机，需要在相机上完成一次主机注册 | 一键跳「主机注册」+ 相机端画面指引 |
| 连接位被占用 | 相机当前已连着别的设备，同一时刻只能连一个 | 分步腾挪引导（P1-3） |
| INIT_EVENT 失败 | 相机未接受事件通道，请让相机停在「WiFi 连接（STA mode）」等待画面 | 图示 |
| 地址不可达 / TCP 超时 | 分两条文案（不再是同一个 `camera_unreachable`） | 检查项：是否还在相机热点上 / 是否开了移动数据 |
| 冷却中 | 正在等相机释放上一次连接（还剩 N 秒） | **倒计时上屏**（对手连"剩余冷却"都写进文案，我们没有） |
| 权限被拒 | 具体是哪一个权限 | 深链去设置 |

> **硬要求**：每一条都要有**深链落点**。GAP-08 原文批评的就是"预检面板只有文案、**没有
> 「去设置」深链落点**"。只改文案不改深链，等于没改。

## 九、一句话总结

**v2.7 不追功能，追证据**：先把"能复现、有数字、可被外人验证"立起来（G1），再把"连不上"
变成用户下一步能照做的动作（G2），顺手补一条对手独有、成本极低的工作流（G3）。
在对手 Android 版进场前，我们手里要有**别人拿不出的证据**，而不是多一堆没人验过的功能。
