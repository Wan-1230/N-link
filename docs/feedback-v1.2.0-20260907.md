## 二、Bug / 缺陷

| # | 问题 | 备注 |
|---|------|------|
| B1 | **仍然无法查看相册** | 同一用户前后两次强调，是最痛的点 |
| B2 | **相册快速滑动翻片时出现卡住 / 花屏 / 堆叠现象** | 快速浏览场景触发，疑似图片加载/回收与滑动节奏不匹配；与 N1（大库加载）同源 ⚠️ 原始表述经整理者转述，细节待与原反馈核对 |
| B3 | 相册滑到底后，需要滑回去才能继续操作 ⚠️ | 疑似加载更多/回弹逻辑问题 |
| B4 | **STA 模式一直无法发现相机**（Z50II 用户反馈：AP 连接正常） | 群友反馈后，**开发者本人（小万）STA 模式同样无法连接** → 大概率是普遍性 bug，而非机型级问题 |
| B5 | 相册导入后，手机相册里看不到新照片，要手动刷新才出现 ⚠️ | 媒体库刷新/扫描问题 |

## 三、体验优化建议

| # | 建议 | 提炼 |
|---|------|------|
| O1 | 不需要"下载中"的遮罩盖住界面，只显示进度和完成状态即可 | 下载态 UI 做减法 |
| O2 | 相册希望有**计数统计**：如"还剩多少张未下载" | 加已下载/未下载角标或计数 |
| O3 | 导入的照片应**立即出现在手机相册**，而不是要手动刷新 | 与 B5 是同一件事 |
| O4 | "未下载"筛选在全部下载完后，就看不到全部照片了 ⚠️ | 筛选态下仍应能浏览全部 |

## 四、新功能 / 性能需求

| # | 需求 | 提炼 |
|---|------|------|
| N1 | 卡里有 **200GB 照片，一次性加载会卡死** | 核心诉求：**分页/增量加载**（一次只加载最近几十张，滚动再加载）。与 B3、O4 本质上是同一件事：**相册大库加载策略需要重做** |
| N2 | Z50II 用户：希望支持下载/预览已在相机上输出的照片 ⚠️ | 与"无法查看相册"（B1）同源，不同机型的表现 |

---

## 五、结论与优先级建议

好评集中在 **USB 通道读卡 + 传送进度** 方向被认可；痛点高度收敛于四件事：

1. **部分机型（Z6II / Z50II）看不了相册**（B1 / N2）
2. **大卡（200G 级）全量加载卡死，需要分页化**（N1 / B2 / B3 / O4）——相册大库加载策略需要重做，快速滑动时的卡顿/花屏/堆叠（B2）是同一根源在交互层的表现
3. **导入后媒体库不刷新**（B5 / O3）
4. **STA 模式发现不了相机**（B4）——开发者本人复现同样无法连接，**大概率是普遍性 bug**，优先级应上调

若排 v1.3.0，建议优先级：STA 发现相机（普遍性连接 bug）> 相册大库分页加载 + 机型相册兼容 > 导入后媒体库即时刷新 > 下载态 UI 减法与计数统计。
